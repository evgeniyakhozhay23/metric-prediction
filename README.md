## Прогнозирование метрик

### Источник
Karpov Courses, курс "Симулятор Аналитика", https://karpov.courses/simulator

Данные с 02.05.2026 до текущего дня (обновляются в режиме реального времени). В анализе использованы данные до 07.09.2026. Данные предоставлены в рамках курса, хранятся в Clickhouse.

### Структура данных
Провожу работу с данными стартапа приложения с лентой новостей (feed_actions) и мессенджером (message_actions). 

Таблица feed_actions- информация о действиях пользователей в приложении ленты новостей:
- user_id - идентификационный номер пользователя
- post_id - номер поста
- action - вид действия пользователя в ленте (категориальная переменная). Значения - like и view.
- time - дата и время действия пользователя в ленте новостей
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента
### Инструменты
- Jupiter Notebook, выгрузка данных из Clickhouse
- Библиотека Orbit для построения моделей и прогнозирования метрик
### Условия кейса
Чем активнее пользователи приложения – тем выше нагрузка на сервера. И в последнее время нам всё чаще приходят жалобы, что приложение подвисает. Необходимо внести свой вклад в задачу – спрогнозировать, как изменится активность пользователей в течение ближайшего месяца.

### Цель и задачи проекта
**Цель:** сделать прогноз метрик активности пользователей на ближайший месяц

**Задачи:**
- Выбрать основную метрику для прогнозирования и временное разрешение
- Выбрать дополнительные регрессоры для модели
- Принять решение о возможном горизонте прогнозирования с учетом имеющегося диапазона данных
- Построить модель и выбрать наиболее удачную

### Построение моделей
- Выбранная метрика: **количество действий на пользователя (actions_per_user)**
- Было построено 6 моделей прогнозирования с последовательным добавлением параметров: модели без регрессоров алгоритмом MAP и MCMC, модель с добавлением 2 регрессорами (алгоритмом MCMC), модель с добавлением 3 регрессоров (алгоритмом MCMC), модель с регрессорами и регуляризацией, добавлением damped_factor)
- Нет четко выраженной сезонности, она не включена в модель
- Прогноз построен на месяц вперед

Добавленные регрессоры: 

- По дням недели: day - день недели, is_weekend - является ли день выходным
- С 12 до 18 июня проводился флешмоб, резко возросла активность пользователей. Переменная is_flashmob = 1 в эти дни, а в другие дни принимает значение 0, так как в будущем никаких таких акций не запланировано.
### Оценка и сравнение качества моделей
- Проведен расчет **информационного критерия**: BIC для моделей с алгоритмом MAP и WBIC для моделей с алгоритмом MCMC
- **Бэктестинг**: с горизонтом прогнозированиям 7 и 14 дней (для 30 дней не хватает данных).
- С параметрами из бэктестинга получаю лучшее значение параметра damped_factor
- Выбор лучшей модели с наиболее низким значением информационного критерия
### Вывод
- Лучшая модель - модель с добавлением параметра damped_factor, регуляризацией и регрессорами.
- Предполагается умеренный восходящий тренд метрики в ближайший месяц
- Для предсказаний в модели построен довольно широкий доверительный интервал. Предполагается возможный большой разброс значений.
